Most timetabling software is priced and built for a whole university. Chalkline is built for the department that just needs the week to be right.

Personal timetables

Each lecturer sees and edits only their own week. Administrators can open anyone's grid, or a combined view of the whole department at once.

Questions we get asked

Do students need an account?

No. You publish a link and they open it. There is nothing for them to sign up for, install or remember, which is the only way a student-facing timetable ever gets used.

Can we run it on our own servers?

Yes. Chalkline is a single container with a PostgreSQL database, and the repository includes step-by-step guides for Azure, AWS and Google Cloud, as well as running it on your own machine. Nothing is locked to a vendor.

What happens to our data if we stop paying?

Nothing is deleted. The account drops back to the free plan, so public pages and calendar links switch off, but every timetable stays exactly as it was and you can export it as a spreadsheet at any time.

Does it replace our student record system?

No, and it does not try to. It handles the weekly teaching timetable, and connects to whatever else you run through its API and webhooks.

Can two lecturers share a room?

By default no, because that is usually a mistake. If your department genuinely shares rooms, an administrator can turn the check off in the institution settings.

How is our data kept?

Each institution's data is separate and no request can reach across that boundary. Passwords are stored as bcrypt hashes. If you host it yourself, the data stays on your own infrastructure entirely.
